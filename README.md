# thien

Two NYC job boards driven by one pipeline. Static pages, no build step, no
server — the data files are generated by re-probing every candidate company's
public ATS and keeping what matches a *profile*.

| Board | Page | Profile | Looking for |
|---|---|---|---|
| Thien · Analyst | `index.html` | `profiles/thien.json` | Strategic / Operations / Data / BI analyst roles in NYC |
| Sean · Game Art | `sean.html` | `profiles/sean.json` | Game-art roles in NYC — concept, 3D, character, environment, technical art, animation, VFX |

Both are the same renderer (`js/board.js`) pointed at different config. Adding
a third board is a JSON file and an HTML file, not a fork.

## Running locally

```sh
python3 -m http.server 8000
# http://localhost:8000          Thien's board
# http://localhost:8000/sean.html  Sean's board
```

Apply-tracking persists to `localStorage` under each profile's `storageKey`
(`thien_applied`, `sean_applied`), so marking a role applied on one board
doesn't touch the other.

## The pipeline

```
profiles/<id>.json ─┬─→ refresh-companies.py ──→ shard JSON ─┐
  filters           │      fetch + filter, sharded            ├→ merge-shards.py
  candidate pool    │      and internally parallel            │       ↓
  scoring + labels  │                                         │  merge-additive.js
                    │                                         │       ↓
                    │                                         │  check-dead.js --prune
                    │                                         │       ↓
                    │                                         └→ js/<id>-data.js
                    └─→ build-profile.js ────────────────────────→ js/<id>-profile.js
                                                                       ↓
                                                                verify-board.py
```

One command runs all of it:

```sh
scripts/pipeline.sh sean            # one board
scripts/pipeline.sh sean thien      # several
SHARDS=8 JOBS=16 scripts/pipeline.sh sean
```

Stages: fetch (N parallel shards × M concurrent ATS probes) → merge shards →
additive merge into the data file → prune postings the ATS no longer lists →
rebuild the browser profile → verify. Nothing but the fetch stage touches the
network, so a failure anywhere else is a real bug.

`.github/workflows/refresh-boards.yml` runs the same script every morning and
commits the diff.

## The agentic half

Two Claude Skills cover the parts that need judgement rather than a schedule:

- **`.claude/skills/job-pipeline`** — refreshes a board, fanning the fetch
  stage across one subagent per shard and doing the whole-dataset stages once,
  in the main thread. Says when to skip the agents entirely and just run
  `scripts/pipeline.sh`.
- **`.claude/skills/job-scout`** — grows a board's candidate pool: find
  employers, resolve each one's ATS slug, verify it against the live API, and
  append it. The pool is the ceiling on everything downstream, so this is the
  usual fix for a thin board.

Ask Claude to "refresh Sean's board" or "add more NYC game studios to Sean's
board" and the matching skill loads.

## Profiles

`profiles/<id>.json` is the single source of truth for a board. The fetch stage
reads the filters and the candidate pool; `build-profile.js` compiles the rest
into `js/<id>-profile.js` for the browser.

```jsonc
{
  "dataFile": "js/sean-data.js",     // where the fetch stage writes
  "storageKey": "sean_applied",      // localStorage key for applied-state
  "companies": [                     // candidate pool, unioned first-wins by id
    "profiles/sean.companies.json",
    "profiles/thien.companies.json"
  ],
  "filters": {
    "geoInclude":        "…",        // location must match
    "titleCityExclude":  "…",        // title naming another city wins over location
    "titleInclude":      "…",        // core disciplines
    "titleIncludeAdjacent": "…",     // adjacent craft…
    "adjacentVerticals": ["gaming"], // …but only at these companies
    "levelRules":  [{ "key": "senior", "match": "…" }],
    "levelDefault": "mid"
  },
  "categories": [ { "key": "…", "label": "…", "match": "…" } ],
  "scoring":    { "coolness": …, "replyProb": …, "passProb": …, "penalties": … }
}
```

Sean's profile carries the one non-obvious rule worth knowing: brand/graphic/
creative-direction titles count as adjacent craft, but only at companies whose
output *is* visual work (`adjacentVerticals`). A brand designer at a game
studio or an agency is the same hands on a different brief; one at a bank is a
different job.

### Fit scoring

```
fit = coolness × P(reply) × P(bar-pass) × penalties
```

percentile-mapped across that board's own role pool onto 0.5–10.0. Every table
lives in the profile — `scoring.coolness.map` (hand-scored 1–10 per company),
`scoring.replyProb.stageTable` (funding stage → reply rate),
`scoring.passProb.titleRules` (title regex → probability delta), and
`scoring.groups` + `scoring.penalties` for structural mismatches. Tuning a
board never means editing JavaScript.

## Adding a company

Append to `profiles/<id>.companies.json` — but verify the slug first, since a
wrong one fails silently:

```sh
python3 scripts/refresh-companies.py --profile sean --only <new-id> -v
python3 scripts/verify-board.py sean
```

`-v` prints how many postings were on the board when none matched, which
separates "wrong slug" from "filters too tight". Supported ATS backends: Ashby,
Greenhouse, Lever, Workable, Workday, Teamtailor, SmartRecruiters.

## Adding a board

1. `profiles/<id>.json` — filters, categories, scoring, `dataFile`,
   `storageKey`, `dataGlobal`, `profileScript`
2. `profiles/<id>.companies.json` — or reuse an existing pool
3. `scripts/pipeline.sh <id>` — generates `js/<id>-data.js` and
   `js/<id>-profile.js`
4. copy `sean.html`, swap the two `<script>` sources and the nav link

## Verifying

```sh
python3 scripts/verify-board.py --all
```

Checks that every profile regex compiles in both Python and V8, that
`categoryFallback` and every emitted level name a real tab, that the generated
profile script is in step with its JSON, that no two candidates point at the
same ATS board, and that no data file carries a duplicate company or a
non-https link. The pipeline runs it as its last stage; CI runs it again.

## A note on Sean's board being small

NYC-located game-art postings on public ATS boards number in the low tens at
any given moment — the pipeline probes ~680 companies to find them. Ten to
twenty roles is a healthy day. Zero is a filter bug; a hundred means the
adjacent lane has slipped its leash.
